# 秒级主动买卖攻势（TFI）设计与参数标定

> 目标：把告警从「分钟级量能突变」推进到「秒级的连续主动扫单」，用秒级数据里独有的
> 主动买卖方向字段，抓住国家队（中央汇金 / 国新 / 诚通一类）在宽基 ETF 上的入场瞬间。
>
> 代码：`server/services/tickImpulse.js`（算法）、`server/services/tickImpulseService.js`（预警链路）、
> `server/services/alertService.js`（落库与文案）、`scripts/backtest-tick-impulse.js`（标定与回放）。

---

## 1. 为什么不能把分钟级算法直接搬到秒级

`volumeSurge` 是按「分钟成交量 / 近 20 分钟中位量」判定的。把它按 1 秒粒度重跑会立刻失效：

| 秒级数据的特点 | 直接套用分钟级算法的后果 | 本算法的处理 |
| --- | --- | --- |
| **成交是稀疏事件流**：没有成交的秒上游快照时间不前进，根本不产生数据点 | 15 秒里可能只有 3–6 个点，「每秒成交量 / 基线每秒成交量」在地量秒上轻易出现几十倍 | 判定单位改成 **15 秒桶的累计额**，并设桶内最小有效秒数（3 秒） |
| **单笔重尾**：偶发一笔几百万的大单 | 单桶尖峰被当成异动，乌龙指 / 单笔调仓全部误报 | 要求**连续 3 桶同向**，单桶孤峰一律不成立 |
| **有方向字段**：外盘 / 内盘是交易所按主动买、主动卖统计的累计量 | 分钟级靠「价格突破」反推方向的办法在这里是信息浪费，而且会漏掉护盘 | 直接用 `（Δ外盘 − Δ内盘）× 100 × 现价` 作为净额，**价格只做加分项，不做门槛** |
| **噪声与信号的区别在持续时间**：无方向放量（指数再平衡、新闻、算法拆单）通常只持续 5–25 秒 | 只看瞬时幅度无法区分，因为放量本身两边都成立 | 波次合并 + 连续桶确认 + 绝对额门槛三道过滤 |
| **国家队不会只买一只** | 单只标的上 5000 万可能是一家机构调仓 | **跨宽基族共振**：沪深300 / 中证500 / 科创50 同时同向才升到最高级 |

一句话：分钟级算法看的是「量」，秒级能看的是「方向 + 连续性 + 共振」，这是两种不同的信息结构。

## 2. 算法结构

```
秒级点（ts, price, amtDelta, netDelta, imba）
   │
   ├─ 分桶（15 秒）          桶内：成交额、主动净额、买/卖秒数、开高低收、盘口失衡均值
   │
   ├─ 稳健基线（前 20 桶，同交易时段，不跨午休）
   │     基线成交额 = median(前 20 桶成交额)
   │     净额波动   = max(MAD × 1.4826, 基线成交额 × 8%)
   │
   ├─ 形态判定（四道同时成立）
   │     net ≥ 50 万（绝对）        ratio = net / 基线成交额 ≥ 0.6
   │     buyShare = net / 桶成交额 ≥ 0.2        z ≥ 4
   │
   ├─ 连续性确认（连续 3 桶弱达标）→ 确认后把波头回溯补齐
   │
   ├─ 波次合并（间隔 < 90 秒、单波 ≤ 10 分钟）
   │
   └─ 跨标的共振（120 秒窗口内 ≥ 2 个宽基族同向）→ 强度升一级
```

### 2.1 为什么基线用「成交额」而不是「净额」

净额的中位数在无信号时约等于 0，没有可以滚动的中心；而成交额的中位数是稳定的活动水平。
所以用 `net / 基线成交额` 作为相对强度，它同时自带「标的规模归一」：
510300 单日 86 亿和 588000 单日 20 亿，0.6 的门槛含义是一致的。

### 2.2 为什么价格不做硬门槛

分钟级 `volumeSurge` 用「价格突破前 20 分钟极值」把方向从量能里逼出来，因为分钟线没有主动买卖字段。
秒级有 `netDelta`，方向是内生已知的。反过来，国家队护盘的典型形态是**下跌中主动承接**——
要求向上突破会把最值得提示的入场直接过滤掉。因此价格只用于强度加分（桶内位移 ≥ 0.12% 加一级）。

### 2.3 为什么波头要回溯补齐

「连续 3 桶确认」如果只从第 3 桶开始算事件，每一波都会丢掉开头 2 桶的净额，也会把
「这一波从 9:56:15 开始」说成「从 9:56:45 开始」。而「从几点开始、一共买了多少」恰好是判断
国家队入场最关键的两个数字。补救办法：第 3 桶确认成立时，把它前面连续达标的桶一并补进来。
补的动作发生在确认之后，所以仍然是因果的（那个桶延迟 15–45 秒才被确认，但时间戳是真实的）。

### 2.4 为什么阈值作用在「整波累计净额」而不是单桶峰值

单桶 800 万连续 4 桶（累计 3200 万）和单桶 3200 万的调仓，是完全不同的两件事，
用户关心的是前者。因此规则阈值是整波累计额，告警文案里再给出「峰值 XX 万/桶」与「N 桶 / 时长」。

### 2.5 跨标的共振为什么是最强判据

单只 510300 上出现 5000 万主动净买，可能是一家机构调仓、也可能是做市商对冲；
同一分钟内沪深300、中证500、科创50 **三族**同时出现同向攻势，只可能是一揽子买入。
族划分见 `server/config/index.js` 的 `FAST_FAMILY_OF`。同族两只（如 510300 + 510310）不落共振，
因为那更可能是套利资金在 ETF 之间平移。

## 3. 参数标定

### 3.1 为什么用合成数据

秒级历史行情没有公开来源（免费接口只给当前快照，分笔历史要付费）。首个交易日之前，
库里只有收盘那一刻的 15 行快照，无法回测。所以用统计特征可控的合成秒级流来回答两个问题：

1. 纯粹噪声的一天，算法每小时误报几次？
2. 注入一段真实扫单形态，多久能抓到？

合成模型（`scripts/backtest-tick-impulse.js`）的三个假设都来自秒级数据的已知性质：

- **成交重尾**：每秒成交额服从对数正态（σ=1.05），中位数量级按 510300 单日 86 亿反推为 900 万/15 秒桶；
- **订单流方向自相关**：主动买占比用 AR(1)（ρ=0.72，稳态 σ≈0.1）模拟连续几秒偏买，而不是白噪声；
- **无方向放量**：每 8 小时约 30 次 3–7 倍量能、持续 5–25 秒、方向随机的流动性突发——这是误报的主要来源。

这不是「证明算法有效」，而是把参数从拍脑袋变成有数字支撑的取舍。真实数据进来后必须用
`--replay` 重算，并以真实误报率为准。

### 3.2 结果（8 组参数 × 20 个随机种子 × 80 个噪声小时）

| 参数组 | 检出事件（次/小时） | 告警级误报（次/小时） | 注入攻势检出率 | 波次起点偏差 |
| --- | --- | --- | --- | --- |
| **默认 0.6 / 3 桶 / z4** | 0.03 | **0.01** | **93%** | 0s |
| 0.6 / 2 桶 / z4 | 0.20 | 0.11 | 98% | 0s |
| 0.8 / 3 桶 / z4 | 0.01 | 0.01 | 89% | 0s |
| 0.4 / 3 桶 / z4 | 0.03 | 0.01 | 93% | 0s |
| 0.6 / 4 桶 / z4 | 0.00 | 0.00 | 74% | 0s |
| 0.6 / 3 桶 / z3 | 0.03 | 0.01 | 94% | 0s |
| 0.6 / 3 桶 / z5 | 0.03 | 0.01 | 91% | 0s |
| 0.6 / 3 桶 / 单桶 100 万 | 0.03 | 0.01 | 93% | 0s |

关键取舍：

- **2 桶 → 3 桶**：告警级误报从 0.11 降到 0.01 次/小时（差 10 倍），检出率从 98% 降到 93%。
  按 15 只 × 4 小时测算，2 桶每天会多出约 6 条噪声告警，3 桶约 0.6 条。选 3 桶。
  代价是确认延迟从 30 秒变成 45 秒——对持续 1–5 分钟的真实扫单可以接受。
- **4 桶**：检出率掉到 74%，说明 45–60 秒的短促扫单被砍掉，太钝。
- **相对门槛 0.4 → 0.8**：0.4 与 0.6 在本样本上误报相同，但纯噪声日的净额比值 p99.9 达 2.11
  （最大值 4.67，来自 7 倍量能的无方向突发）。把门槛压到 0.4 等于贴近噪声的分位尾部，
  换真实数据（尾更肥）就会成片误报。取 0.6 留出安全边际。
- **z=3 → 5**：检出率 94% → 91%，误报不变。z 在本算法里主要起「随波动率自适应」的作用，
  主判据是 ratio 与连续性，所以维持 z=4。
- **单桶门槛 50 万 vs 100 万**：本样本无差别（510300 量级下 ratio 门槛远高于绝对门槛）。
  取 50 万是为了让小规模标的（科创50、中证 A500）也能产生事件，规模门槛交给规则层。

### 3.3 注入攻势的检出情况

| 波次 | 量能倍数 | 主动买占比 | 默认参数 | 2 桶参数 |
| --- | --- | --- | --- | --- |
| 09:55 | ×6 | 82% | 检出，起点对齐 | 检出 |
| 10:40 | ×4 | 76% | 检出，起点对齐 | 检出 |
| 13:15 | ×8 | 85% | 检出，起点对齐 | 检出 |
| 14:30 | ×2.5 | 68% | 检出，起点对齐 | 检出 |

「起点对齐」意味着波头回溯生效：告警里的时间戳是攻势真实开始的那一秒，不是确认时刻。

## 4. 与分钟级 VSD 的分工

| | `volume_surge`（分钟级） | `tick_impulse`（秒级） |
| --- | --- | --- |
| 覆盖 | 全池 ~120 只 | 核心池 15 只（国家队常买宽基） |
| 粒度 | 1 分钟 | 15 秒桶，1 秒采样 |
| 方向来源 | 价格突破前 20 分钟极值 | 外盘 / 内盘增量（原生主动买卖） |
| 判定 | 单根 K 线倍数 + z | 连续 3 桶 + 波次合并 + 跨族共振 |
| 首次告警延迟 | 约 1–2 分钟 | 约 45–60 秒 |
| 定位 | 面的覆盖：谁在异动 | 点的确认：是不是同一只手在扫 |

两者独立落库、独立规则、独立冷却，互不覆盖。分钟级负责全网发现，秒级负责对重点标的做二次确认。

## 5. 已知边界

1. **门槛来自合成数据**，不是真实成交回放。开盘后必须用
   `node scripts/backtest-tick-impulse.js --replay` 在真实秒级库上重算，据实调整。
2. **秒级数据保留 2 天**（`FAST_RETENTION_DAYS`）。要做跨日研究需加大保留或增加按日降采样归档。
3. **绝对门槛按 510300 量级设定**。成交额小一个数量级的标的要更大的相对波动才达标，
   需要单独覆盖时可为其建一条更低阈值的规则（适用范围选「指定代码」）。
4. **15 秒桶与 1 秒采样之间有一层错配**：上游快照若 3 秒才前进一步，`amtDelta` 是 3 秒的量，
   落在后一个桶上。对桶累计额影响很小，但会让桶内「买/卖秒数」少于真实秒数。
5. **「国家队常买」是经验清单**，不是官方披露名单；共振判定依赖这份清单的族划分。
